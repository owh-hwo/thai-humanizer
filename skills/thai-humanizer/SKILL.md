# Thai Humanizer

ทำให้ข้อความอ่านเหมือนผู้เขียนเขียนเอง ไม่ใช่แชตบอตหรือเครื่องแปล **คงสิ่งที่ข้อความพูดไว้ทั้งหมด** ห้ามเพิ่มข้อเท็จจริง ตัวเลข ชื่อ วันที่ คำพูด ประสบการณ์ส่วนตัว หรือการอ้างอิงที่ไม่ได้มาจากต้นฉบับหรือผู้ใช้ ห้ามเปลี่ยนระดับความมั่นใจ (พบว่า / น่าจะ / อาจ) ห้ามยกระดับ "สัมพันธ์กับ" เป็น "ทำให้" และห้ามให้ข้อสรุปคมกว่าหลักฐานที่ปูไว้ เป้าหมายคือคุณภาพภาษาสำหรับผู้อ่าน ไม่ใช่การหลบเครื่องตรวจ AI

เกณฑ์รับงาน: **ความหมายเดิมครบ ความสัมพันธ์ระหว่างข้อความชัด ระดับภาษาเหมาะกับงาน** จำนวนร่องรอยที่ลดลงเป็นข้อมูลประกอบ ไม่ใช่เป้าหมาย

## เส้นทางภาษาไทย

### 0. รู้ก่อนว่าข้อความเป็นประเภทใดและผู้อ่านคือใคร

อย่าสั่งตัวเองแค่ว่า "ให้เป็นธรรมชาติ" เพราะจะได้ภาษาพูดในบทความวารสาร หรือภาษาราชการในบทความเว็บ ดูตารางเทียบท้าย `thai-prose-patterns.md`

**เดาก่อน ถ้าเดาไม่ได้ ถามรอบเดียว** เดาจากข้อความและคำสั่ง: มีอ้างอิงและหัวข้อแบบบทความวิจัย = วิชาการ, ขึ้นต้น "เรียน" หรือมีเรื่องที่ตอบ = จดหมาย/อีเมลตอบ, หลายข้อความสั้นมีคำลงท้ายหรือชื่อเล่น = แชต ถ้ายังไม่ชัด หรือสองประเภทให้ผลต่างกันมาก (อีเมลถึงอาจารย์กับอีเมลถึงเพื่อนร่วมงาน) ให้ถามผู้ใช้หนึ่งรอบ ไม่เกิน 3 ข้อ แล้วเริ่มทำทันที ไม่ถามซ้ำ

1. ประเภทงาน: บทความวิชาการ / บทความเว็บหรือโพสต์ / จดหมายหรืออีเมลตอบ / แชตหรือข้อความสั้น
2. ผู้อ่านและความสัมพันธ์: อาจารย์หรือผู้บังคับบัญชา ลูกค้า เพื่อนร่วมงาน คนทั่วไป (กำหนดสรรพนาม คำลงท้าย และระดับความสุภาพ)
3. มีตัวอย่างงานเขียนของผู้ใช้เอง หรือข้อความเดิมในเธรดไหม (ถ้ามี ใช้เป็นหลักเหนือกติกาในไฟล์)

ใช้เครื่องมือถามแบบตัวเลือก (เช่น AskUserQuestion) ถ้ามี ไม่มีก็ถามเป็นข้อความสั้น ๆ **ไม่ถาม** เมื่อผู้ใช้ระบุประเภทงานมาแล้ว เมื่อสกิลอื่นเรียกใช้ (โหมดฝัง สกิลผู้เรียกเป็นผู้กำหนดประเภทงาน) หรือเมื่อข้อความบอกประเภทชัดอยู่แล้ว ถ้าถามไม่ได้ (รันอัตโนมัติ) ใช้ค่าที่เดาได้ และระบุสมมติฐานไว้ในผลลัพธ์

- **วิชาการ** (รายงานวิจัย บทความวิพากษ์ ตำรา วิทยานิพนธ์): ทางการ ใช้ "มิได้ หาก ย่อม" ได้ แยกผล หลักฐาน การตีความ และข้อเสนอให้ชัด ("ผู้เขียนเห็นว่า" ใช้เมื่อต้องแยกเจ้าของความเห็น ไม่ต้องมีทุกย่อหน้า) คำเรียกคน กริยา และภาพเปรียบต้องอยู่ระดับเดียวกับศัพท์วิชาการ ("อดีตพนักงาน" ไม่ใช่ "คนที่ไปแล้ว", "สัมภาษณ์" ไม่ใช่ "ตามสัมภาษณ์") ห้ามแตะข้อความกฎหมาย ข้อความยกตรง ตัวเลข การอ้างอิง
- **ทั่วไป** (บทความให้ข้อมูล คู่มือ อีเมล โพสต์): ระดับภาษาตรงกับผู้อ่าน คงเสียงของผู้เขียน (อารมณ์ขัน ความเห็น วงเล็บแทรก "ผม/เรา") ไว้ รายการและตัวหนาใช้ได้ แต่ **ห้ามแต่งประสบการณ์หรือเรื่องส่วนตัวขึ้นเอง** เพื่อให้ดูเป็นคน และศัพท์ช่างต้องอธิบายครั้งแรกถ้าผู้อ่านเป็นมือใหม่
- **จดหมาย / อีเมลตอบ** และ **แชต / ข้อความสั้น**: อยู่ในกลุ่มทั่วไปสำหรับสคริปต์ แต่มีธรรมเนียมเฉพาะ (คำขึ้นต้นลงท้ายตามฐานะ ตอบทีละประเด็นตามลำดับที่ถาม ความยาวตามบทสนทนา สรรพนามและคำลงท้ายตามที่ผู้ใช้ใช้กับคนนั้นอยู่แล้ว) ดูโปรไฟล์ประเภทงานย่อยท้าย `thai-prose-patterns.md` ห้ามยกระดับความสุภาพหรือลดระดับเองเพื่อให้ "เป็นธรรมชาติ"
- ถ้าผู้ใช้ให้ตัวอย่างงานเขียนของตนเอง อ่านก่อน แล้วเลียนความยาวประโยค คำเชื่อม และระดับภาษาของตัวอย่าง ตัวอย่างของผู้ใช้สำคัญกว่ากติกาในไฟล์

### 1. ถ้ายังไม่ได้เขียน: ร่างให้ถูกตั้งแต่ต้น

อ่าน `references/thai-prose-patterns.md` แล้ว
- เขียนจากโน้ตภาษาไทย ไม่ใช่จากประโยคภาษาอังกฤษ ถ้าแหล่งเป็นภาษาอังกฤษ ให้สรุปเป็นโน้ตไทยสั้น ๆ ก่อน ("ใคร ทำอะไร กับใคร ได้ผลอย่างไร มีข้อจำกัดอะไร") ปิดต้นฉบับ แล้วเขียนจากโน้ต เสร็จค่อยเปิดกลับมาเทียบ ตัวเลข ความสัมพันธ์ ขอบเขต และระดับความมั่นใจ
- กำหนดหน้าที่ของแต่ละย่อหน้าก่อน (ตั้งปัญหา นิยาม รายงานผล เทียบงาน แย้ง เสนอ) แล้วเลือกแม่แบบ (ก-ญ) เฉพาะย่อหน้าที่หน้าที่ตรงกัน แม่แบบเป็นทางเลือก ไม่ใช่ข้อบังคับ
- เรียงประโยคตามหัวเรื่อง: ขึ้นต้นด้วยสิ่งที่กำลังพูดถึง (ผู้กระทำ สิ่งที่ได้รับผล เวลา หรือเงื่อนไข) ละประธานได้เมื่ออ้างกลับได้ทางเดียว กล่าวซ้ำเมื่อเปลี่ยนผู้กระทำ
- ทำรายการคำหลัก (แนวคิด ตัวแปร กลุ่มตัวอย่าง) แล้วใช้คำเดียวตลอดเรื่อง ไม่หลบคำซ้ำด้วยคำใกล้เคียง
- ข้อความที่ต้องคงตามตัวอักษร (ตัวบทกฎหมาย นิยามทางการ คำพูดที่ยกมา) ครอบด้วย `[ตัวบท]...[/ตัวบท]` ให้ขั้นต่อไปข้าม

### 2. นับร่องรอยก่อนอ่าน

```bash
python -I <skill-dir>/scripts/thai_style_check.py draft.md --top 5 --genre auto
```

ได้ตารางร่องรอยแต่ละชนิดต่อ 1,000 คำ เทียบกับเกณฑ์ทดลองที่ปรับจากตัวอย่างบทความตีพิมพ์จำนวนน้อย และตัวอย่างพร้อมเลขบรรทัด `--genre general` ปิดการเตือนที่ใช้เฉพาะงานวิชาการ (จุดยืนผู้เขียน บูลเล็ตในร้อยแก้ว "มัน") จดหมายและแชตใช้ `--genre letter` หรือ `chat` ซึ่งนับแบบ general `auto` เดาจากการอ้างอิงและชื่อหัวข้อ ข้อความใน `[ตัวบท]` และในเครื่องหมายคำพูดจะถูกข้าม ตัวเลขเป็นสัญญาณเรียกตรวจ ไม่ใช่คำตัดสิน ต้องอ่านประโยคจริงทุกจุดก่อนแก้ ข้อความสั้น (อีเมล 100 คำ) ให้ดูจำนวนจริง ไม่ดูอัตรา ใช้ `--strict` ให้ exit 1 เมื่อมี WARN สำหรับ CI หรือ hook

### 3. อ่านและแก้ตาม `references/thai-humanizer.md`

1. อ่านทั้งส่วนหนึ่งรอบ ทำรายการร่องรอยที่พบพร้อมจำนวนครั้ง (รวมผลจากสคริปต์) และรายการคำหลักที่ต้องคงที่
2. ตรวจร่องรอยระดับความหมายก่อน (ชุด ก ในไฟล์): ประโยคสรุปทุกประโยคเทียบกับหลักฐาน คำอ้างย้อนทุกคำแทนด้วยนามเต็มได้ทางเดียวไหม ความสัมพันธ์ยังเป็น "สัมพันธ์" หรือกลายเป็น "ทำให้" คู่ตรงข้าม "ไม่ใช่ X แต่ Y" ตัด X ออกเกินหลักฐานไหม
3. แก้ทีละส่วน เขียนประโยคใหม่ทั้งประโยคจากใจความ ไม่ใช่แทนคำทีละคำ "นอกจากนี้" ที่เปิดย่อหน้าติดกันหรือไม่ได้เพิ่มประเด็นใหม่จริง ให้แทนด้วยประโยคที่บอกว่าจะเพิ่มอะไร แต่**อย่าใช้กติกาแบบเหมารวม** "ถูกหักภาษี" "ถูกต้อง" "แม้...ก็ตาม แต่" เป็นไทยปกติ "ได้รับการ" ไม่ใช่คำแทน "ถูก" และห้ามแต่งผู้กระทำขึ้นเพื่อหลบกรรมวาจก ถ้าพบข้อความที่เกินหลักฐาน (ต้องเติม "อาจ" หรือตัด "ทั้งหมด" จึงจะตรงหลักฐาน) **อย่าแก้เงียบ ๆ ในฉบับเกลาสำนวน** ให้แยกเป็นข้อเสนอแก้สาระพร้อมเหตุผล ส่งคู่กับฉบับเกลา แล้วให้ผู้ใช้ตัดสิน
4. ตรวจซ้ำว่าไม่มีอ้างอิงหาย ตัวเลขไม่เปลี่ยน สิ่งที่งานวัดไม่เปลี่ยน (งานที่วัด "ยอดขายที่รายงาน" ห้ามกลายเป็น "ธุรกิจเห็นผล") ผลไม่มีนัยสำคัญไม่กลายเป็น "ไม่มีผล" ประโยคกฎหมายยังตรงตัวบท คำปฏิเสธและคำบอกขอบเขต ("เฉพาะ เพียง ยัง ทั้งหมด") ยังเกาะข้อความเดิม ความยาวที่หดต้องมาจากตัดคำเปล่า ไม่ใช่ตัดเงื่อนไข
5. ตรวจกลไกภาษาไทยที่การแก้มักทำพัง (ท้าย `thai-prose-patterns.md`): เว้นวรรคตามหน่วยความคิด ไม้ยมก คำช่วยกริยา "ได้ อยู่ ไป มา แล้ว ยัง" ลักษณนามหน้าคำชี้เฉพาะ สรรพนาม "เรา" ขอบเขตคงที่
6. อ่านออกเสียงในใจทีละประโยค ถามสองข้อแยกกัน: คำเกาะกลุ่มถูกไหม และระดับภาษาตรงกับประเภทงานไหม (บทความวารสาร: "อาจารย์เขียนลงวารสารแบบนี้ไหม" บทความเว็บ: "คนที่รู้เรื่องนี้เล่าให้ผู้อ่านแบบนี้ไหม")
7. รันสคริปต์ซ้ำ ดูว่าไม่มีร่องรอยใหม่ที่เกิดจากการแก้ ตัวเลขที่ไม่ลดไม่ได้แปลว่าแก้ไม่สำเร็จ ถ้าอ่านแล้วแต่ละจุดทำหน้าที่ถูก

### 4. ผู้ตรวจที่ไม่เห็นภาษาอังกฤษ (แนะนำสำหรับงานยาวหรือที่อ้างแหล่งอังกฤษมาก)

ส่ง subagent ใหม่ให้ **เฉพาะข้อความภาษาไทย** ไม่ให้ต้นฉบับอังกฤษ บทคัดย่อ หรือโน้ต สั่งให้ทำเครื่องหมายประโยคที่ "เดาได้ว่าต้นฉบับเป็นภาษาอังกฤษ" ประโยคที่อ่านแล้วไม่เหมือนคนไทยเขียน และประโยคที่ระดับภาษาหลุดจากชิ้นงาน พร้อมเสนอทางเขียนใหม่ ห้ามแตะ `[ตัวบท]` และข้อความในเครื่องหมายคำพูด ผู้เขียนรับข้อเสนอทีละจุดหลังเทียบกับแหล่ง เพราะข้อเสนอสำนวนก็ทำความหมายแคบลงได้ ถ้ามี CLI ของโมเดลอื่นในเครื่อง (เช่น `codex exec`) ใช้เป็นผู้ตรวจอิสระได้ โดยสั่งให้วิจารณ์ในฐานะนักภาษาศาสตร์ไทยระดับประโยค

## ผลลัพธ์ที่ส่งกลับ

- **ข้อความที่วางมา (ค่าเริ่มต้น):** ร่างที่แก้ รายการร่องรอยที่ยังเหลือและเหตุผลที่คงไว้ แล้วฉบับสุดท้าย ให้ตัวอย่างก่อน-หลัง 3-5 จุดที่เปลี่ยนมากที่สุด และระบุจุดที่น้ำหนักข้อความเปลี่ยนโดยตั้งใจ
- **โหมดไฟล์:** ผู้ใช้ระบุไฟล์ ให้แก้เฉพาะร้อยแก้วในไฟล์นั้น คงโค้ด คำสั่ง path YAML ตาราง ลิงก์ `[ตัวบท]` แล้วสรุปสั้น ๆ ว่าเปลี่ยนอะไร
- **โหมดฝังในงานอื่น:** สกิลอื่นเรียกใช้ (เช่น เขียนบทความ ตอบอีเมล) ส่งกลับเฉพาะข้อความสุดท้าย

## เมื่อไม่ควรแก้

- คำพูดที่ยกมา ชื่อเรื่อง ชื่อเฉพาะ ข้อความกฎหมาย และข้อความที่กำลัง *พูดถึง* สำนวนนั้น
- รายละเอียดที่เป็นเสียงของผู้เขียนจริง: ตัวอย่างเจาะจง ความเห็นที่ยังค้างคา วงเล็บแทรก การแก้ตัวเองกลางประโยค
- ร่องรอยที่พบเพียงจุดเดียวและผู้เขียนอาจตั้งใจ (เช่น "มิใช่...หากแต่..." 1 ครั้งทั้งเรื่อง) หลายร่องรอยในย่อหน้าเดียวกันจึงเป็นเหตุให้แก้ ไม่ใช่จุดเดียว
- คำซ้ำที่ทำหน้าที่รักษาหัวเรื่อง ("ต้นทุนเริ่มต้นสูง แต่ต้นทุนรายปีต่ำ") นามนามธรรมที่เป็นชื่อแนวคิด กรรมวาจกที่วัตถุเป็นหัวเรื่อง
- ข้อความภาษาไทยที่อ่านแล้วสะดุดเพราะเนื้อหายาก ไม่ใช่เพราะสำนวน แก้สำนวนไม่ช่วย
