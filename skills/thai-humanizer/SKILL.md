# Thai Humanizer

ทำให้ข้อความอ่านเหมือนผู้เขียนเขียนเอง ไม่ใช่แชตบอตหรือเครื่องแปล **คงสิ่งที่ข้อความพูดไว้ทั้งหมด** ห้ามเพิ่มข้อเท็จจริง ตัวเลข ชื่อ วันที่ คำพูด หรือการอ้างอิงที่ไม่ได้มาจากต้นฉบับหรือผู้ใช้ และห้ามเปลี่ยนระดับความมั่นใจ (พบว่า / น่าจะ / อาจ) เป้าหมายคือคุณภาพภาษาสำหรับผู้อ่าน ไม่ใช่การหลบเครื่องตรวจ AI

## เลือกเส้นทางตามภาษา

| ข้อความ | ทำตาม |
|---|---|
| ภาษาไทย (ทั้งหมดหรือส่วนใหญ่) | เส้นทางภาษาไทยด้านล่าง |
| ภาษาอังกฤษ | `references/humanizer-en.md` ทั้งไฟล์ (Humanizer v3.1 ของ Siqi Chen รวมไว้ตามต้นฉบับ) |
| ปนกัน เช่น บทความไทยที่มี Abstract อังกฤษ | แยกส่วน ทำแต่ละส่วนตามภาษาของมัน แล้วตรวจว่าสองภาษายังพูดเรื่องเดียวกัน |

## ทรัพยากร

| ไฟล์ | ใช้เมื่อ |
|---|---|
| `references/thai-prose-patterns.md` | **ก่อนหรือขณะร่าง**: แม่แบบย่อหน้าภาษาไทยวิชาการ 10 แบบ คลังคำเชื่อม/กริยา และตารางสำนวนแปลที่ต้องเลี่ยง (บอกว่า *ให้* เขียนอย่างไร) |
| `references/thai-humanizer.md` | **หลังร่าง**: ร่องรอยภาษา AI และสำนวนแปลที่ต้องหาและแก้ พร้อมข้อควรระวังตอนแก้ (บอกว่า *อย่า* เขียนอย่างไร) |
| `scripts/thai_style_check.py` | นับร่องรอยต่อ 1,000 คำพร้อมเลขบรรทัด (คำเชื่อมซ้ำต้นย่อหน้า คำขยายเกินจริง "ซึ่ง/ถูก/การ/ของ" ซ้อน "มีนัยสำคัญ" นอกบริบทสถิติ จุดยืนผู้เขียน) |
| `references/humanizer-en.md` | ข้อความภาษาอังกฤษ: 26 patterns, วิธีทำงาน, voice, รูปแบบผลลัพธ์ |

สคริปต์ใช้ Python 3.9+ ทำงานได้โดยไม่ต้องติดตั้งอะไร ถ้ามี `pythainlp` จะนับคำและความยาวประโยคได้แม่นขึ้น (`pip install pythainlp`)

## เส้นทางภาษาไทย

### 0. รู้ก่อนว่าข้อความเป็นประเภทใด

- **วิชาการ** (บทความวารสาร วิทยานิพนธ์ รายงานวิจัย): ต้องเป็นทางการ ใช้ "มิได้ หาก ย่อม" ได้ ต้องมีจุดยืนผู้เขียน ("ผู้เขียนเห็นว่า") ห้ามแตะข้อความกฎหมาย ข้อความยกตรง ตัวเลข การอ้างอิง
- **ทั่วไป** (บทความเว็บ โพสต์ อีเมล คู่มือ): ใช้ร่องรอยชุดเดียวกัน แต่ปล่อยให้ระดับภาษาตรงกับผู้อ่าน ไม่ต้องยกเป็นภาษาวิชาการ และคงเสียงของผู้เขียน (อารมณ์ขัน ความเห็น วงเล็บแทรก) ไว้
- ถ้าผู้ใช้ให้ตัวอย่างงานเขียนของตนเอง อ่านก่อน แล้วเลียนความยาวประโยค คำเชื่อม และระดับภาษาของตัวอย่าง ตัวอย่างของผู้ใช้สำคัญกว่ากติกาในไฟล์

### 1. ถ้ายังไม่ได้เขียน: ร่างให้ถูกตั้งแต่ต้น

อ่าน `references/thai-prose-patterns.md` แล้ว
- เขียนจากโน้ตภาษาไทย ไม่ใช่จากประโยคภาษาอังกฤษ ถ้าแหล่งเป็นภาษาอังกฤษ ให้สรุปเป็นโน้ตไทยสั้น ๆ ก่อน ("ใคร ทำอะไร กับใคร ได้ผลอย่างไร") ปิดต้นฉบับ แล้วเขียนจากโน้ต เสร็จค่อยเปิดกลับมาเทียบตัวเลข
- เลือกแม่แบบย่อหน้า (ก-ญ) ให้แต่ละย่อหน้า: เปิดด้วยข้อเท็จจริง เกริ่นงานที่อ้าง เทียบงานสองชิ้น ใส่จุดยืน ขยายประเด็น แย้ง ปิดหัวข้อ
- ประโยคเดินด้วย ผู้กระทำ → กริยา → กรรม → เงื่อนไข
- ข้อความที่ต้องคงตามตัวอักษร (ตัวบทกฎหมาย นิยามทางการ คำพูดที่ยกมา) ครอบด้วย `[ตัวบท]...[/ตัวบท]` ให้ขั้นต่อไปข้าม

### 2. นับร่องรอยก่อนอ่าน

```bash
python -I <skill-dir>/scripts/thai_style_check.py draft.md --top 5
```

ได้ตารางร่องรอยแต่ละชนิดต่อ 1,000 คำ เทียบกับเกณฑ์ที่ปรับจากบทความตีพิมพ์จริง และตัวอย่างพร้อมเลขบรรทัด ข้อความใน `[ตัวบท]` และในเครื่องหมายคำพูดจะถูกข้าม ตัวเลขเป็นสัญญาณ ไม่ใช่คำตัดสิน ต้องอ่านประโยคจริงทุกจุดก่อนแก้ ใช้ `--strict` ให้ exit 1 เมื่อมี WARN สำหรับ CI หรือ hook

### 3. อ่านและแก้ตาม `references/thai-humanizer.md`

1. อ่านทั้งส่วนหนึ่งรอบ ทำรายการร่องรอยที่พบพร้อมจำนวนครั้ง (รวมผลจากสคริปต์)
2. แก้ทีละส่วน เขียนประโยคใหม่ทั้งประโยคจากใจความ ไม่ใช่แทนคำทีละคำ แทนที่ "นอกจากนี้" ด้วยประโยคที่บอกว่าจะเพิ่มอะไร แทนที่ประธานนามธรรมด้วยผู้กระทำ แต่**อย่าใช้กติกาแบบเหมารวม** "ถูกหักภาษี" "ถูกต้อง" เป็นไทยปกติ
3. ตรวจซ้ำว่าไม่มีอ้างอิงหาย ตัวเลขไม่เปลี่ยน สิ่งที่งานวัดไม่เปลี่ยน (งานที่วัด "ยอดขายที่รายงาน" ห้ามกลายเป็น "ธุรกิจเห็นผล") ผลไม่มีนัยสำคัญไม่กลายเป็น "ไม่มีผล" ประโยคกฎหมายยังตรงตัวบท ความยาวไม่หดเกินร้อยละ 10
4. อ่านออกเสียงในใจทีละประโยค ถามว่า "ถ้าคนไทยที่รู้เรื่องนี้พูดให้เพื่อนฟัง จะเรียงคำแบบนี้ไหม" ถ้าไม่ เรียงใหม่
5. รันสคริปต์ซ้ำ ดูว่าตัวเลขลดจริง และไม่มีร่องรอยใหม่ที่เกิดจากการแก้

### 4. ผู้ตรวจที่ไม่เห็นภาษาอังกฤษ (แนะนำสำหรับงานยาวหรือที่อ้างแหล่งอังกฤษมาก)

ส่ง subagent ใหม่ให้ **เฉพาะข้อความภาษาไทย** ไม่ให้ต้นฉบับอังกฤษ บทคัดย่อ หรือโน้ต สั่งให้ทำเครื่องหมายประโยคที่ "เดาได้ว่าต้นฉบับเป็นภาษาอังกฤษ" หรืออ่านแล้วไม่เหมือนคนไทยเขียน พร้อมเสนอทางเขียนใหม่ ห้ามแตะ `[ตัวบท]` และข้อความในเครื่องหมายคำพูด ผู้เขียนรับข้อเสนอทีละจุดหลังเทียบกับแหล่ง เพราะข้อเสนอสำนวนก็ทำความหมายแคบลงได้

## ผลลัพธ์ที่ส่งกลับ

- **ข้อความที่วางมา (ค่าเริ่มต้น):** ร่างที่แก้ รายการร่องรอยที่ยังเหลือและเหตุผลที่คงไว้ แล้วฉบับสุดท้าย ให้ตัวอย่างก่อน-หลัง 3-5 จุดที่เปลี่ยนมากที่สุด
- **โหมดไฟล์:** ผู้ใช้ระบุไฟล์ ให้แก้เฉพาะร้อยแก้วในไฟล์นั้น คงโค้ด คำสั่ง path YAML ตาราง ลิงก์ `[ตัวบท]` แล้วสรุปสั้น ๆ ว่าเปลี่ยนอะไร
- **โหมดฝังในงานอื่น:** สกิลอื่นเรียกใช้ (เช่น เขียนบทความ ตอบอีเมล) ส่งกลับเฉพาะข้อความสุดท้าย

## เมื่อไม่ควรแก้

- คำพูดที่ยกมา ชื่อเรื่อง ชื่อเฉพาะ ข้อความกฎหมาย และข้อความที่กำลัง *พูดถึง* สำนวนนั้น
- รายละเอียดที่เป็นเสียงของผู้เขียนจริง: ตัวอย่างเจาะจง ความเห็นที่ยังค้างคา วงเล็บแทรก การแก้ตัวเองกลางประโยค
- ร่องรอยที่พบเพียงจุดเดียวและผู้เขียนอาจตั้งใจ (เช่น "มิใช่...หากแต่..." 1 ครั้งทั้งเรื่อง) หลายร่องรอยในย่อหน้าเดียวกันจึงเป็นเหตุให้แก้ ไม่ใช่จุดเดียว
- ข้อความภาษาไทยที่อ่านแล้วสะดุดเพราะเนื้อหายาก ไม่ใช่เพราะสำนวน แก้สำนวนไม่ช่วย
